# Agent Note: 用独立 HumanSL 概率损失任务实现容错复盘

Status: implemented

## Problem

普通相邻局面胜率差可定位明显失误，却不足以识别此前让后续选择变难的走法。单一平均损失又掩盖尾部风险，未搜索候选会导致概率统计过度乐观。

## Decision

2026-10-05 在代码中实现独立容错模块：保存完整 HumanSL 概率与候选评价，分开目差和胜率指标，显式保留未知质量；当前局面、全盘扫描和有限后续分支比较共用独立 JSONL worker。复用现有 Batch 互斥生命周期，不向原有强度估计 DTO 填入不同语义的数据。当前行为以 [模块说明](../../../docs/engine/tolerance-review.md) 为准。

## Alternatives considered

- 仅增加「平均损失难度」指标：不能表达同一均值下的不同尾部与未知质量。
- 将普通引擎 policy 视为人类落点概率：其模型目标与 HumanSL 不同，不能满足本次分析口径。
- 将现有智子云实时响应直接接入：尚未确认完整 HumanSL 字段与档位，首版明确禁用。
- 遍历全部未来路径形成整局风险：计算量及人类模型校准超出本次已验证方法；使用明确标注的代表性分支。

## Consequences

结果可复核和跨阈值重算，原棋谱与原评分保持独立。代价是额外人类模型、SSH Python supervisor、搜索预算和本地存储。缓存依赖模型与配置身份；配置含外部 include 时禁用。有限分支结果不能自动认定较早走法造成失败。未来若云服务提供可验证的完整能力，再扩展来源适配。

## Verification

Rust 黄金夹具核对真实 waffle 响应的覆盖率、未知质量、两类可接受质量、尾部和期望损失；规则/摆子/停一手/分支与任务部分保存测试覆盖实现边界。前端检查旧任务隔离与阈值变化。真实远端、构建、GUI 和未验证事项记录在 [日期 QA](../../../docs/qa/TOLERANCE_REVIEW_20261005.md)，这些不等同于安装包发布验收。
