# Agent Note: HumanSL 40 迁入原棋力界面并复用普通分析

Status: implemented

## Problem

原 Java 实验入口要求用户选择裁判和人类网络、单独重跑全盘分析；用户明确要求只在原模型下拉框选择、在已有界面显示，并将同一功能集成到 Tauri 重构版。

## Decision

2026-10-15 将同一 40 特征 booster 和特征协议移入 TypeScript，在原测评模块加入可选模型。
普通分析帧为只读输入，独立本地 HumanSL 进程只提供三档单访问策略；沿用已验证的资源下载，不新增设置窗口或另写下载器。
补算使用独立取消状态，不抢占现有普通分析生命周期。结果按文档/路径和任务代次隔离，策略按协议与网络/引擎身份缓存。
当前行为和验证边界归 [模块说明](../../../docs/engine/humansl40-strength.md)。

## Alternatives considered

- 重跑固定 b18/v500：接近参考训练输入分布，但用户已明确拒绝重复普通分析。
- 将普通 policy 当成人类策略：语义不同，不能代替三个 HumanSL 档位。
- 复用容错复盘的独占全盘生命周期：会打断普通分析，且容错模块还需要独立设置、较深搜索和不同结果结构，不适合此处。

## Consequences

保留原 20TUN 默认和全部原功能，界面统一，普通搜索数据可复用；代价是本地 HumanSL 网络和少量附加推理。
输入可不同于参考训练，因此只标记实验评估，不承诺参考精度；低覆盖难度保持缺失。
私密棋谱和原始标签不能进入源码、模型包或 Git，策略缓存只保存在应用数据目录。

## Verification

已运行数值对照、完整前端测试、Rust 桌面单元测试和显式本地真实策略引擎测试，完成前端/应用构建。
原生窗口自动化超时，不能把构建与后端验证说成完整 GUI 验收；详见模块说明。
