# 文档迁移协议

适用于用户要求重组、拆分、合并或迁移文档。单纯审计不执行迁移；明确要求迁移即提供范围内授权，不再为常规可逆编辑重复询问。

## 清点与映射

记录输入范围及版本；工作区有已有修改时保留它们的完整内容。逐项建立映射：`旧路径/章节 → 保留、迁移、拆分、合并或删除 → 新路径/章节 → 依据 → 入站引用 → 验证`。可用 skill 脚本的 `--inventory` 获取 Markdown 路径与 SHA-256，但机器清单不能代替章节级内容分析。

先识别生成源、翻译对、正式发布路径及冻结历史。更新生成源再生成派生文件；成对内容共同处理。相对链接、标题锚点、HTML/wiki 链接、代码注释、导航、CI、配置和外部书签都属于引用影响，不能只查 `.md` 内的普通链接。

## 执行

先准备目标内容和可恢复副本，再移动或删除来源；没有版本控制时先备份受影响原文件。只处理映射内内容。拆分当前事实与历史理由时保留条件、例外、失败路径和独有依据，不将假设升级为事实。

旧决定只有完全被吸收且独有理由、备选、代价和验证缺口均保留后，才可依项目规则删除。部分替代应保留仍有效部分并链接新决定。冻结归档不改写、不自动修其正文链接；需要兼容入口时在活动目录处理。无法恢复的历史明确标记未知。

生命周期转换同时更新路径、状态及正文：proposed 转 implemented 要写实际交付内容和证据；未实现的项保留待办或独立提案，不靠移动文件宣告完成。

## 验收与回退

迁移前后逐项对照映射，检查每项内容有去处。全仓库检索旧路径及已改标题，检查入站/出站链接和导航。执行已有文档构建、相关源代码测试及发布预览中适用的部分。脚本对 HTML、wiki、复杂 Markdown 及锚点仅提示边界，不能替代站点自身校验。

报告迁移文件清单、内容保留证据、引用修复、实际验证和未完成项。需要回退时仅恢复本次修改；先检测后续变更，避免整仓库 reset 或覆盖他人工作。文件数变少、字数减少或脚本退出 0 都不能单独证明迁移完成。
