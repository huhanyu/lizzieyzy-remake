# HumanSL 40 棋力测评

## 当前使用方式

在原有分析模块选择“测评”，从“棋力模型”下拉框选择 **HumanSL 40**。
XGBoost 20TUN 保持默认；模型选择会记住，切换吻合度、问题手和发挥水准页继续使用同一组测评样本。
不增加独立棋力窗口，不要求设置裁判网络、HumanSL 路径或档位。
原有 HumanSL 对弈、容错和训练模块不变。

首次选中会检查完整分析。每方至少需要 6 手，候选点和相邻根局面必须完整、属于同一分析任务，且明确绑定当前棋谱/节点。
选择路径是当前节点的祖先及其主延续，最多前 210 手；同手数的兄弟分支不能混用。
19 路、交替落子的普通棋谱可用；让子、摆子、指定行棋方暂未验证，拒绝评估。
未分析位置直接略过，不另行启动普通全盘分析。

补算只获取 1d、5d、9d 三档策略，每档 maxVisits=1，历史开启、根对称数 2、额外人类探索概率 0。
普通候选点、顺序、先验概率、目差和胜率直接取已有分析帧，策略引擎的候选点/目差/胜率全部丢弃。
它使用独立进程和取消令牌，不占用/替换原实时、全盘或云端分析的独占槽，也不发布主分析帧。

本地 KataGo 从已保存配置、打包运行时、PATH 和 macOS 常用 Homebrew 路径检测。HumanSL 从校验安装的受管资源及现有模型同目录检测；缺少时在当前面板提供约 99 MB 的下载按钮，沿用现有资源下载、校验、取消机制。
无本地 KataGo 时提示使用原有引擎设置安装，不要求为此模型配置分析命令。
已存在的人类模型在补算前重新核对 SHA-256：
`637746e44f0efe00ad1245a50aa9bbf0716efe364c43965ead97bd6835d84ab5`。

## 结果与刷新

原测评表显示双方段位、目损、一选率、好手率、HumanSL 9d 难度和策略覆盖率。
难度仅平均覆盖率至少 90% 的局面；没有可靠局面时显示空值，模型特征保留 NaN，不填零。
覆盖率表示已评估候选点覆盖的人类策略概率质量，不是可信度或战术正确性的证明。
段位仍描述单盘表现，实验模型没有经过完整低段验证。

主分析候选点/访问数更新时，会用已有策略重算特征，不反复启动策略任务。
新增完整分析的位置可用刷新按钮补入；任务进行时提供取消按钮。
切换文档、路径或模型以及卸载组件会取消旧任务；旧进度和迟到结果不能进入新棋谱。
取消保留此前完整缓存，但不把未完成任务当作新结果。

## 模型协议

内置 `humansl40_booster.json` 是原 Java 版本的同一份 40 特征 XGBoost，预测截断到 [0,12]，不套用 20TUN 的校准器、启发式门控或固定标准差。
特征为标准匹配/损失/阶段特征 20 个、稳健损失与极端局面特征 8 个，以及三档 HumanSL 特征 12 个。
特征顺序、round-to-even、严格一选、阶段回退和反转窗口沿用原版本；树推理支持 NaN 的默认分支。

参考训练使用固定 b18 网络、v500、5d 人类探索 0.5；当前用户流程明确复用已有分析。
不同网络、计算量、PDA、候选点宽度等可能改变输入分布和策略覆盖，不能沿用固定训练协议的精度结论。
当前实现因此保留实验标记；不自动补跑参考裁判分析。

## 缓存与私密数据

策略缓存在应用数据目录 `strength-humansl40/cache/`，日志和私有配置也位于该目录体系，不在仓库。
键包含规则、贴目、完整落子前缀、初始执棋方、档位、全部查询参数、算法版本、引擎和配置摘要及网络摘要。
首次返回与缓存读取采用一致的浮点表示；完整缓存命中不启动进程。
错误、警告、搜索中或不规范的概率响应不缓存。缓存只存策略数组，不存原始 SGF、棋手标签或普通分析。
私密参考夹具和验收证据只能放仓库外或被忽略的 `target/`，不进入 public/models、测试资源或 Git。
下载仅请求公开模型文件，不上传棋谱。本功能不执行 Git 提交或推送。
