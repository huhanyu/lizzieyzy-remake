# 容错复盘

在复盘区选择「局面训练」，展开「高级分析与设置」查看容错复盘。普通训练入口见 [局面训练](position-training.md)。它把 HumanSL 的合法落点概率与 KataGo 对候选的损失评价组合，帮助检查某个选择之后是否更难下。结果独立于原有问题手和棋力评分，不改变其算法。

## 操作与模型

1. 配置支持 analysis JSONL 与 `-human-model` 的 KataGo、局面评估模型、人类模型及分析配置。SSH 模式填写目标机路径；可按顺序设置最多四跳，目标机需 Python 3，所有跳点须已配置 SSH 信任与认证。多跳沿用 SSH agent 转发，不复制私钥。设置保存在本机 app-data 的 `tolerance-review/config.json`。
2. 主棋盘停在要诊断的落子**之前**。例如诊断第 135 手，先选第 134 手节点。
3. 「分析当前局面」加深当前局面并补搜高概率未知候选。「扫描全盘」扫描主线全部局面，再按实战胜率损失与低可接受质量排序，加深预算内的重点局面；排序只标记检查目标。
4. 「比较后续容错」比较实战首手与近等值替代走法。可输入坐标或 `pass` 手动指定替代；每个首手探索至多两种合理对手应手，再沿引擎首选推进，检查至多三次己方决策。比较数量和搜索量可调。
5. 切换目差/胜率口径、调整阈值无需重算；展开表格查看全部合法落点。时间轴点击可定位原棋谱。容错面板在复盘区内部滚动，宽表格可单独横向滚动。变化预览使用独立小棋盘和滑条，可另存含变化及容错注释的 SGF；原棋谱不被改写。完整 JSON 保留设置、模型指纹、原始响应、逐点损失及部分结果。

首版支持本地进程和 SSH。智子云现有分析响应未验证能提供完整 `humanPolicy`、人类档位及候选评价，入口禁用，不能将普通 `policy` 作为替代。当前项目实测使用远端 TF11（`tf3-b11c768-s12252M-d6398M`）与 `b18c384nbt-humanv0`；用户私有主机与路径不写入仓库。

默认档位 `proyear_2023` 表示职业落点风格代理，不是某位棋手真实或经校准的选择概率。也可选择业余段级位。评估模型决定损失，人类模型决定概率，两者职责不同。

## 数值口径

所有引擎响应强制 BLACK 视角；损失计算再转换为当前行棋方。目差优先使用 `scoreLead`，缺失时才用 `scoreMean`。目差与胜率分别以充分搜索候选中最好的对应值为基准，不能混用两个基准。

- 可接受质量：所有合法落点中，已知损失不超过阈值的 HumanSL 概率和。默认目差 ≤ 1，胜率损失 ≤ 5 个百分点。
- 大损失质量：已知损失达到阈值的概率和。默认目差 ≥ 3，胜率损失 ≥ 10 个百分点。
- 已知部分期望损失：已知候选 `概率 × 损失` 的和，是完整期望损失的下界。
- 未知质量：未搜索、访问不足或仅有对称复制评价的候选概率和。只修正概率总和的微小浮点漂移，绝不按已搜索质量重新归一化。

默认粗扫 2048、加深 8192 次访问；候选最低 128 次，目标覆盖率 0.97，每局面最多补搜 8 个候选。补搜单候选预算最多 2048（配置最低候选访问量更高时使用该门槛），覆盖率不足继续显示未知，不伪装达标。weightless HumanSL 搜索可能使报告的主树访问少于配置预算，因此同时保留预算与实际访问。

自动替代首手要求目损失 ≤ 1 且胜率损失 ≤ 5pp；合理对手应手要求其自身目损失 ≤ 1.5，优先引擎首选及人类概率高的走法。后续统计按代表分支逐条展示，不是对所有未来路径积分，不能报告成整局输棋概率，也不自动给较早选择归因。明显失误与此前低容错位置应分别检查。

## 生命周期、持久化与边界

任务冻结 SGF 全文、节点、规则、贴目、初始摆子与行棋方，并保留完整分支历史。根节点让子、`PL`、停一手受支持；中途重新摆子或 `PL` 会明确拒绝，须另存起始局面。带 UTF-8 BOM 的 SGF 可解析。全盘最多 1500 手、5000 节点。

任务借用现有 Batch 独占槽。前端停止后台补线与前景会话，保存原来的本地/SSH/云端配置。取消只发出信号，worker 结束引擎、保存部分结果并释放槽后才发送终态。SSH supervisor 隔离引擎进程组，收到关闭控制、EOF 或 HUP 时回收子进程；必须收到 `riskClosed` 才自动恢复前景。连接异常未确认退出时保留结果并提示人工核对。退出应用会取消该模块的任务。

UI 先监听再提交，事件同时核对 job ID 与 SGF SHA-256；原文不同的数据不混用。任务运行时禁止编辑原棋谱与竞争使用引擎。重新打开同一棋谱可恢复最近结果；中断任务重新运行，复用可验证查询缓存，而非从未确认的远端执行点续跑。

`app-data/tolerance-review/` 保存 `reports/`、`queries/`、`evidence/`、配置及每谱最新结果指针。缓存指纹包含算法版本、引擎版本/入口文件哈希、两个模型内容哈希、配置哈希及完整查询（含历史、规则、贴目、棋力、预算）。配置存在 `@include` 时禁用复用。通过 wrapper 启动时引擎哈希对应 wrapper 文件，底层引擎另由版本输出标识；替换底层同版本二进制后应清理查询缓存。显示阈值不影响原始查询缓存。

当前保留所有任务文件，不自动清理；长时间批量使用需由用户管理磁盘。历史报告是当时模型和预算下的证据，不能与新模型结果悄然合并。
