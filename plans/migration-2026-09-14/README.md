## 独立验收与合入流程
每个任务状态：待派发 → 实施中 → 待验收 → 返工/验收通过 → 已集成。DSH 不得自行标记最终验收通过。
1. DSH 提交：基线标识、改动范围、接口差异、测试命令和实际结果、已知限制、可复现样例。
2. Codex 审查 diff 和边界；检查是否破坏已有未提交工作、重复视角转换、引入假数据或越界改动。
3. 在隔离集成副本应用一个任务并跑相应测试；最终运行 cargo fmt --all --check、cargo clippy --workspace --all-targets -- -D warnings、cargo test --workspace 及前端 npm run build。既有失败单独记录，不能伪报全绿。
4. 真实 KataGo 检查：普通局面、让子、分支、换手、暂停恢复、快速切换、引擎失败。单测使用假引擎允许，但单测不能代替真实引擎验收。
5. 原生 Tauri GUI 操作完成打开→分析→换分支→悬停→试下→退出→保存重开，并检查短窗口布局。浏览器 recorded 预览只用于外观，不能充当分析验收。
6. 记录每项通过/失败/未测及证据，再顺序集成到用户工作区；有失败只退回对应任务，避免全项目返工。
