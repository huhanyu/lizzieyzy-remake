# P1 分析功能补齐

目标：基于现有 GTP 本地/云端传输，补齐核心分析闭环；保持棋盘、统计、调度、参数职责分离。

## 顺序与验收

1. 全盘历史自动补齐：逐真实主线节点计算；不可用插值代替结果。
2. 粗扫再深算：32 visits 基线后按预算加深。
3. 增量补算：仅同文档、同分析上下文缺失或不足预算节点。
4. 暂停续跑：停止命令收到 ACK 后暂停，保留连接及任务进度。
5. 云端 VIP：复用现有会话，不重新登录、不创建第二套协议。
6. 分析范围：范围边界有效，保留计算上一手损失所需父节点。
7. 问题手模块：真实相邻节点计算并能跳转。
8. 问题筛选：黑白、胜率/目差、阈值、排序。
9. 彩色问题概览：颜色与实际损失一致。
10. 吻合度模块：显示覆盖率，缺数据不填零。
11. 吻合口径：topN 与相对计算量阈值可调。
12. 双方平均损失：明确统计样本与视角。
13. allow：仅当前局面候选限制。
14. avoid：仅当前局面候选排除。
15. 搜索限额：时间/visits 达限停止但保留连接。
16. 线程：验证数值，云端不支持时明确拒绝。
17. 广度参数：等待引擎 ACK 后确认生效。
18. PDA：等待引擎 ACK 后确认生效。

## 复用与边界

复用 buildLivePosition、现有帧协议、javaMoveMatch、moveLosses、现有云传输。任务规划、状态机、统计分别独立模块。按 job/generation/turn/document 排除迟到结果；不修改用户当前棋盘来推进后台任务。

## 验证

纯函数测试覆盖范围/缺失/分支/黑白视角；状态机覆盖 ACK 竞态、暂停、取消与过期帧；前端构建、Rust 测试/检查；最后真实引擎与原生 UI 验收。构建成功不等于功能验收完成。
